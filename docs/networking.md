# ProbeOS LAN networking

ProbeOS is usable with no network. The probeos-network OpenRC service
discovers wired Ethernet interfaces and attempts IPv4 DHCP at boot. A DHCP
failure is logged and ignored; it never prevents the local report, TUI, or
local-only Web UI from starting. ProbeOS is a DHCP client, never a DHCP server.

Offline operation has no externally reachable listener: the read-only Web/API
is loopback-only on TCP 8080, while DHCP may use its standard client port.
Explicit LAN mode exposes only TCP 8080 for that same read-only service. Remote
shell services are not enabled. The runtime security audit fails qualification
when it observes an unexpected listener; see [security](security.md).

The network status shown by the TUI includes interface, link state, IPv4
address/prefix, gateway, link speed and DHCP/manual method. The report's
authoritative network section is generated by probe-identify.

## Runtime commands

These commands change only the running live environment:

    probeos-network status
    probeos-network dhcp eth0
    probeos-network static eth0 192.168.1.147/24 192.168.1.1

Static IPv4 validation requires an address with prefix, such as
192.0.2.20/24; the gateway is optional. No configuration is persisted to disk
by v1.

## Web UI modes

The Web UI service uses port 8080. It starts on 127.0.0.1 by default. In the
TUI, select Network / Web UI -> Enable LAN Web UI to bind all IPv4 interfaces,
then use Show Network Status to find the address:

    http://192.168.1.147:8080/

LAN mode is intended only for trusted local networks. It has no authentication
or TLS and must not be exposed to the Internet. Select Start Local Web UI to
return to the safe loopback binding, or Stop Web UI when finished.

The QEMU qualification uses user-mode networking and a host port forward to
prove DHCP plus HTTP/API operation without Internet access. The existing
-nic none qualification remains the offline baseline.
